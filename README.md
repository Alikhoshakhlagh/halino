# حالینو (Halino)

وب‌اپلیکیشن پیشنهاد محتوا و فعالیت بر اساس مود و ترجیحات کاربر.
فرانت جدا با HTML، SCSS و JS ساده؛ بک‌اند جنگو با API؛ فارسی، راست‌به‌چپ و موبایل‌محور.

## راه‌اندازی

### بک‌اند

```bash
cd backend
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_base
python manage.py import_titles
python manage.py createsuperuser
python manage.py runserver
```

- API: <http://127.0.0.1:8000/api/>
- پنل مدیریت: <http://127.0.0.1:8000/admin/>

### فرانت

جنگو باید روشن باشد. بعد `frontend/index.html` را با Live Server یا دکمه‌ی مرورگر PyCharm باز کن، یا:

```bash
cd frontend
python -m http.server 5500
```

و برو به <http://127.0.0.1:5500/>. آدرس بک‌اند در `frontend/js/config.js` است.

ورود با شماره موبایل و کد یک‌بارمصرف است. در حالت توسعه (`HALINO_OTP_CONSOLE = True`)
کد در کنسول جنگو چاپ و روی صفحه‌ی تأیید نشان داده می‌شود.

### تغییر استایل‌ها

مرورگر `css/main.css` را می‌خواند و این فایل از SCSS ساخته می‌شود:

```bash
cd frontend
sass --watch scss/main.scss css/main.css --no-source-map
```

## زبان طراحی

مینیمال و پاستیلی، با فضای تنفس زیاد و فقط تم روشن.

- **رنگ‌ها فقط در `scss/_root.scss` هستند.** زمینه‌ی کرم `#fbf9f5`، متن قهوه‌ای تیره `#3a3631`،
  دکمه‌ی سبز ملایم `#bfd7a8`. از زرد برای پس‌زمینه استفاده نمی‌شود.
- **رنگ مود و دسته از روی نوعشان می‌آید.** `data-mood` و `data-category` روی المان می‌نشینند و
  `base/_data-colors.scss` رنگ را از `:root` برمی‌دارد. فیلد `color` دیتابیس دیگر روی ظاهر اثری ندارد.
- **کد تکراری نداریم.** استایل‌های مشترک در `_mixins.scss` و کامپوننت‌ها در `js/components` هستند.
- **فونت وزیرمتن** به‌صورت لوکال در `assets/fonts`.

### انیمیشن‌ها

ورود نرم محتوا، بازخورد لمس، باز شدن شیت و رسم نمودار با CSS هستند و فقط شمارنده‌ی آمار
در `js/animations.js` است. `prefers-reduced-motion` همه را خاموش می‌کند.

### لینک محتوا و جست‌وجو

هر محتوای بیرونی فیلد `external_url` دارد و در صفحه‌ی آیتم به‌صورت دکمه نشان داده می‌شود. داده‌ی
پادکست، مقاله، کافه و مکان در `backend/content/linked_items.py` است و `seed_base` آن را وارد می‌کند.
صفحه‌ی هر دسته جست‌وجو دارد و دسته‌ی کافه و مکان، تهران و اصفهان را جدا نشان می‌دهد.

### چهره‌های مود

هر مود یک چهره‌ی SVG دارد (`js/components/face.js`). فیلد `Mood.face` مشخص می‌کند کدام چهره
کشیده شود. برای نمایش: `createFace(mood, "small")` با اندازه‌های `small`، `medium`، `large` و `fill`.

### گزارش ماهانه در صفحه تقویم

- **شیشه مود:** هر روز ثبت‌شده یک چهره در شیشه؛ ترتیب با seed ثابت به‌هم می‌ریزد.
- **راهنما:** شمارش هر مود، از پرتکرار به کم‌تکرار.
- **نمودار نوسان:** در `js/components/mood-chart.js`؛ محور روزها راست‌به‌چپ است.

با زدن روی هر روز گذشته می‌شود حال آن روز را ثبت یا عوض کرد. برای روزهای گذشته سؤال اضافه‌ای
پرسیده نمی‌شود و پیشنهاد امروز هم عوض نمی‌شود.

### کاربر نمونه

این دستور (داخل `backend`) کاربر `09121234567` را از نو با داده‌ی فیک می‌سازد: حال ۱۲۰ روز،
جواب سؤال‌ها، آیتم‌های انجام‌شده با امتیاز، موارد ردشده و آیتم‌های در حال انجام.

```bash
python manage.py demo_user
```

## موتور پیشنهاد

پروفایل کاربر، مود امروز و هر آیتم همگی به شکل **بردار تگ** بیان می‌شوند و
امتیاز هر آیتم برابر ضرب داخلی دو بردار است. دسته‌بندی فقط برای نمایش است و
نقشی در تطبیق ندارد.

دو دسته پیشنهاد در صفحه امروز که **هیچ‌وقت هم‌زمان دیده نمی‌شوند** — هرکدام یک
پنل تمام‌عرض در یک دِک افقی است و با اسکرول‌اسنپ بین‌شان حرکت می‌کنیم:

| پنل | ورودی | کِی ساخته می‌شود |
|---|---|---|
| **متناسب با حالت** | مود + پاسخ سؤال‌های روز + نصفِ وزن پروفایل | لحظه ثبت یا ویرایش مود |
| **پیشنهاد روز** | دستور مدیر + مناسبت امروز + پروفایل (+ کافه/دورهمی) | اولین بازدید هر روز |

اگر کاربر مود ثبت کرده باشد، پنل «متناسب با حالت» پیش‌فرض است و دکمه‌ی پایین
دِک با انیمیشن می‌بردش به «پیشنهاد روز». اگر مود ثبت نشده باشد، اصلاً پنل اولی
ساخته نمی‌شود و فقط «پیشنهاد روز» وجود دارد.

### پیشنهاد روز از کجا می‌آید

`build_day_layer()` سه ورودی را به‌ترتیب اعمال می‌کند:

1. **دستور مدیر** — روی هر مناسبت می‌شود آیتم‌های مشخصی را «قفل» کرد
   (`Occasion.pinned_items`). این‌ها از فیلتر امتیازدهی رد نمی‌شوند و حتماً
   می‌آیند؛ فقط «نمی‌خوام» کاربر را محترم می‌شمارند.
2. **مناسبت امروز** — از دو تقویم:
   - `source=iran` با تاریخ **شمسی** (نوروز، سیزده‌بدر، شب یلدا، بزرگداشت‌ها)
   - `source=national` با تاریخ **میلادی**، به سبک
     [nationaldaycalendar.com](https://nationaldaycalendar.com/) (روز جهانی کتاب،
     روز جهانی قهوه، روز جهانی ایموجی…)
   تگ‌های مناسبت موقتاً وزن می‌گیرند تا پیشنهاد ویژه بالا بیاید. اگر چند مناسبت
   روی یک روز بیفتند، `priority` بالاتر برنده است و دستور مدیر معمولاً بالاترین.
3. **کافه یا دورهمی** — فقط اگر شناخت ما از کاربر تأییدش کند: شهرش پشتیبانی شود
   **و** وزن تگ‌های «اجتماعی/بیرون از خانه» در پروفایلش مثبت باشد. برای کاربر
   خانه‌نشین این اسلات اصلاً باز نمی‌شود.

فهرست روزهای جهانی در `seed_base.py` یک انتخاب دستی است، نه کپی کامل سایت؛ از
پنل ادمین می‌شود هر چقدر خواستی به آن اضافه کرد.

سه قانون بیرون از فرمول:

1. **گیت شهری** — دسته‌های `needs_city` فقط برای شهرهای پشتیبانی‌شده باز است.
2. **قانون دنباله‌دار** — تا کتاب/سریال فعلی تمام نشده، از آن دسته آیتم جدید
   پیشنهاد نمی‌شود؛ به‌جایش بلوک «در حال انجام» یادآوری می‌کند.
3. **ضد تکرار** — آیتمی که در ۳۰ روز گذشته پیشنهاد شده دوباره نمی‌آید. اگر
   استخر خالی شد، قوانین مرحله‌به‌مرحله شل می‌شوند تا صفحه هرگز خالی نماند.

### دستور مدیر، عملی

در پنل ادمین یک «مناسبت» بساز با منبع «دستور مدیر»، تاریخ امروز، اولویت بالا
(مثلاً ۵۰) و آیتم‌های دلخواه در «آیتم‌های قفل‌شده». اگر فقط برای یک روز خاص است،
فیلد «سال» را هم پر کن تا سال بعد تکرار نشود.

پیشنهادها در جدول `DailyRecommendation` ذخیره می‌شوند، پس رفرش صفحه چیزی را
عوض نمی‌کند. فیلد `score` برای دیباگ در پنل ادمین قابل مشاهده است.

## ML

مدل و نحوه‌ی استفاده در [`docs/ml.md`](docs/ml.md) توضیح داده شده: Naive Bayes چندجمله‌ای
به‌ازای هر کاربر (`journey/ml.py`)، فقط برای بازچینش بخش «متناسب با حالت»، با
آستانه‌ی فالبک ۱۰ رکورد بازخورد.

### مود «غمگین» یعنی چه؟

تصمیم محصولی: نه محتوای هم‌حال، نه شادیِ تصنعی. برای مودهای منفی، تگ‌های
«امیدوارکننده» و «دلگرم‌کننده» وزن مثبت می‌گیرند و «تلخ» با وزن منفی سرکوب
می‌شود. این قاعده در `seed_base.py` (جدول `MOODS`) نوشته شده و بدون تغییر کد،
از پنل ادمین قابل تنظیم است.

## مدل مود

لیست ثابت ۹تایی برای کاربر، ولی هر مود مختصات عددی `energy` و `valence` بین
۲- تا ۲+ دارد. UI ساده می‌ماند و در عوض تقویم و آمار می‌توانند عدد واقعی نشان
بدهند. اضافه‌کردن مود جدید یک ردیف است، نه بازنویسی نگاشت.

## تقویم شمسی

`journey/jalali.py` تبدیل میلادی↔شمسی، طول ماه، سال کبیسه، نام ماه و روز
هفته را بدون هیچ پکیج بیرونی انجام می‌دهد. تاریخ‌ها میلادی ذخیره می‌شوند و
فقط موقع نمایش شمسی می‌شوند.

## داده

- `content/fixtures/top_titles.json` — ۲۰۰ فیلم و ۵۰ سریال برتر. تگ‌ها به‌طور
  خودکار از ژانرها ساخته می‌شوند (`content/taxonomy.py`). برای عوض‌کردن فهرست
  فقط همین فایل را عوض کن: `python manage.py import_titles --file mylist.json --clear`
- کتاب، کافه، ورزش، مدیتیشن، نوشتن، بازی و پادکست در `seed_base.py` به‌صورت
  نمونه آمده‌اند؛ بقیه از پنل ادمین دستی وارد می‌شوند.
- **مهم‌ترین ریسک پروژه همین‌جاست:** موتور بدون آیتم تگ‌خورده چیزی برای گفتن
  ندارد. هر آیتم تازه‌ای که وارد می‌کنی، حتماً دو سه تگ هم برایش بزن.
