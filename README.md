# حالینو (Halino)

وب‌اپلیکیشن پیشنهاد محتوا و فعالیت بر اساس مود و ترجیحات کاربر.
جنگو + تمپلیت، فارسی و راست‌به‌چپ، موبایل‌فرست، موتور پیشنهاد Rule-Based.

## راه‌اندازی

```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_base        # شهر، تگ، دسته، مود، سؤال، مناسبت، آیتم‌های غیرفیلم
python manage.py import_titles    # ۲۵۰ فیلم و سریال برتر با تگ‌زنی خودکار
python manage.py createsuperuser  # برای ورود به پنل ادمین
python manage.py runserver
```

ورود کاربر با شماره موبایل و کد یک‌بارمصرف است. در حالت توسعه
(`HALINO_OTP_CONSOLE = True`) کد به‌جای پیامک در کنسول چاپ و روی صفحه نشان
داده می‌شود، پس نیازی به سرویس پیامک نیست.

- اپ: <http://127.0.0.1:8000/>
- پنل مدیریت: <http://127.0.0.1:8000/admin/>

## ساختار

```
config/     تنظیمات، urlها
accounts/   کاربر سفارشی (ورود با موبایل)، شهر، کد یک‌بارمصرف
content/    تگ، دسته‌بندی، آیتم، مناسبت  ← دانش دامنه اینجاست
journey/    مود، سؤال، پاسخ، وضعیت آیتم، پیشنهاد روز، موتور، تقویم شمسی
templates/  چهار صفحه اصلی + ورود + آنبوردینگ + اسپرایت چهره‌ها
static/css/ سیستم طراحی: توکن‌ها، کامپوننت‌ها، لایت و دارک
```

## زبان طراحی

الهام از Finch (کارت‌های نرم و رنگی)، How We Feel (گرید مود رنگی)، Duolingo
(دکمه چانکی با سایه سخت و فیدبک لمسی) و Daylio (تقویم رنگ‌کدشده).

- **پالت:** بنفش `#7C5CFF` به‌عنوان برند، به‌همراه آبی `#4CC9F0`، صورتی `#F472B6`،
  زرد `#FFC93C`، مرجانی `#FF6B6B`، سبز `#34D399`. زمینه یاسی روشن `#FBF7FF`،
  متن سرمه‌ای `#1B1236` (نه سیاه).
- **رنگ از دیتابیس می‌آید،‌ نه از CSS.** هر دسته و هر مود فیلد `color` دارد و
  تمپلیت آن را به شکل `style="--c: {{ ... }}"` روی المان ست می‌کند. یعنی دسته
  جدید در پنل ادمین، خودش رنگ خودش را به کارت‌ها و تایل‌ها می‌دهد — بدون یک خط CSS.
- **شعاع درشت** (۱۲ تا ۳۲ پیکسل) و **سایه سخت** (`0 3px 0`) به‌جای سایه نرم؛
  با `:active { transform: translateY(3px) }` که حس فشرده‌شدن دکمه را می‌دهد.
- **دارک مود** کامل با `prefers-color-scheme` و پشتیبانی از `data-theme`.
- **فونت وزیرمتن** از Google Fonts با فالبک سیستمی.
- `color-mix()` باعث می‌شود از یک رنگ پایه، تینت پس‌زمینه و سایه ساخته شود و
  لازم نباشد برای هر دسته چند رنگ دستی تعریف کنیم.

### انیمیشن‌ها

همه در `static/js/app.js` و بخش انتهایی `base.css`. اصول:

- **Progressive enhancement** — بدون JS همه‌چیز کار می‌کند (ویزارد آنبوردینگ
  به یک فرم بلند تبدیل می‌شود)، فقط بی‌روح‌تر.
- **`prefers-reduced-motion`** هر حرکتی را خاموش می‌کند؛ کانفتی، شمارنده و
  ورود پلکانی هم پشت همین شرط‌اند.
- **ترنزیشن بین صفحه‌ها** با View Transitions چند‌سندی (`@view-transition
  { navigation: auto }`) — تب‌بار و لوگو بین صفحه‌ها «مورف» می‌شوند نه محو.
- **ورود پلکانی** کارت‌ها با `--i` که JS روی هر المان ست می‌کند و CSS با
  `calc(var(--i) * 55ms)` تأخیر می‌دهد.
- **ثبت مود**: بقیه چیپ‌ها محو، انتخاب‌شده پاپ می‌کند، کانفتی با Web
  Animations API، و بعد از ۴۸۰ms فرم با `requestSubmit(chip)` می‌رود (تا
  مقدار همان دکمه ارسال شود).
- **شیشه مود**: توپ‌ها با تأخیر پلکانی از بالا می‌افتند و کمی می‌پرند.
- **نمودار**: خط با `stroke-dasharray` رسم می‌شود، نقطه‌ها پاپ می‌کنند.
- **شمارنده آمار**: اعداد از صفر بالا می‌روند؛ یک `setTimeout` تضمین می‌کند
  حتی اگر rAF در تب پنهان بایستد، عدد نهایی نوشته شود.
- **ریپل** روی دکمه‌ها، تایل‌ها، تب‌ها و سطرها؛ **details** با ارتفاع نرم
  باز و بسته می‌شود؛ **پیام‌ها** بعد از ۳ ثانیه خودشان می‌روند.
- **ویزارد آنبوردینگ**: هر سؤال یک مرحله با نوار پیشرفت و شمارنده؛
  تک‌انتخابی‌ها خودشان می‌روند مرحله بعد (مثل Habitz).
- **اسپلش ورود**: چهره‌های مود شناور با pop-in پلکانی.
- **PWA**: `manifest.webmanifest` + آیکون SVG؛ روی موبایل «افزودن به صفحه
  اصلی» تمام‌صفحه و بدون نوار مرورگر باز می‌شود.

### چهره‌های مود

به‌جای ایموجی، هر مود یک چهره‌ی تخت و دست‌ساز دارد
(`templates/journey/_mood_sprite.html`). اسپرایت یک بار در `base.html` اینلاین
می‌شود و هر symbol فقط «اجزای صورت» است — دایره‌ی رنگی را `_face.html` می‌کشد.
رنگ اجزا با `color-mix()` از رنگ خود مود مشتق می‌شود، پس یک اسپرایت برای هر ۹
مود و هر دو تم کافی است. فیلد `Mood.face` مشخص می‌کند کدام چهره کشیده شود و از
پنل ادمین قابل تغییر است.

استفاده در تمپلیت:

```django
{% include "journey/_face.html" with mood=mood cls="face--md face--gloss" %}
```

اندازه‌ها: `face--xs` (تقویم) · `face--sm` (راهنما و نوار مود) · `face--md`
(گرید انتخاب مود) · `face--ball` (توپ‌های شیشه) · `face--gloss` براقی اضافه می‌کند.

### گزارش ماهانه در صفحه تقویم

- **شیشه مود** — هر روز ثبت‌شده یک توپ به رنگ مود همان روز. با
  `flex-wrap: wrap-reverse` از کف شیشه پر می‌شود؛ ترتیب توپ‌ها با seed ثابت
  به‌هم می‌ریزد تا طبیعی باشد ولی با رفرش جابه‌جا نشود.
- **راهنما** — شمارش هر مود، مرتب‌شده از پرتکرار به کم‌تکرار.
- **نمودار نوسان مود** — SVG اینلاین؛ محور عمودی خوشایندی از ۲+ تا ۲- و محور
  افقی روزهای ماه به‌صورت **راست‌به‌چپ** (روز ۱ سمت راست). هندسه‌اش در
  `_mood_chart()` داخل ویو حساب می‌شود و تمپلیت فقط می‌کشد.

برای اینکه این صفحه موقع ارائه خالی نباشد:

```bash
python manage.py demo_moods 09121234567 --fill 85
```

## موتور پیشنهاد

پروفایل کاربر، مود امروز و هر آیتم همگی به شکل **بردار تگ** بیان می‌شوند و
امتیاز هر آیتم برابر ضرب داخلی دو بردار است. دسته‌بندی فقط برای نمایش است و
نقشی در تطبیق ندارد.

دو دسته پیشنهاد در صفحه امروز که **هیچ‌وقت هم‌زمان دیده نمی‌شوند** — هرکدام یک
پنل تمام‌عرض در یک دِک افقی است و با اسکرول‌اسنپ بین‌شان حرکت می‌کنیم:

| پنل | ورودی | کِی ساخته می‌شود |
|---|---|---|
| **متناسب با حالت** | مود + پاسخ سؤال‌های روز + نصفِ وزن پروفایل | لحظه ثبت یا ویرایش مود |
| **پیشنهاد روز** | دستور مدیر + مناسبت امروز + پروفایل (+ کافه/دورهمی) | اولین بازدید هر روز |

اگر کاربر مود ثبت کرده باشد، پنل «متناسب با حالت» پیش‌فرض است و دکمه‌ی پایین
دِک با انیمیشن می‌بردش به «پیشنهاد روز». اگر مود ثبت نشده باشد، اصلاً پنل اولی
ساخته نمی‌شود و فقط «پیشنهاد روز» وجود دارد.

### پیشنهاد روز از کجا می‌آید

`build_day_layer()` سه ورودی را به‌ترتیب اعمال می‌کند:

1. **دستور مدیر** — روی هر مناسبت می‌شود آیتم‌های مشخصی را «قفل» کرد
   (`Occasion.pinned_items`). این‌ها از فیلتر امتیازدهی رد نمی‌شوند و حتماً
   می‌آیند؛ فقط «نمی‌خوام» کاربر را محترم می‌شمارند.
2. **مناسبت امروز** — از دو تقویم:
   - `source=iran` با تاریخ **شمسی** (نوروز، سیزده‌بدر، شب یلدا، بزرگداشت‌ها)
   - `source=national` با تاریخ **میلادی**، به سبک
     [nationaldaycalendar.com](https://nationaldaycalendar.com/) (روز جهانی کتاب،
     روز جهانی قهوه، روز جهانی ایموجی…)
   تگ‌های مناسبت موقتاً وزن می‌گیرند تا پیشنهاد ویژه بالا بیاید. اگر چند مناسبت
   روی یک روز بیفتند، `priority` بالاتر برنده است و دستور مدیر معمولاً بالاترین.
3. **کافه یا دورهمی** — فقط اگر شناخت ما از کاربر تأییدش کند: شهرش پشتیبانی شود
   **و** وزن تگ‌های «اجتماعی/بیرون از خانه» در پروفایلش مثبت باشد. برای کاربر
   خانه‌نشین این اسلات اصلاً باز نمی‌شود.

فهرست روزهای جهانی در `seed_base.py` یک انتخاب دستی است، نه کپی کامل سایت؛ از
پنل ادمین می‌شود هر چقدر خواستی به آن اضافه کرد.

سه قانون بیرون از فرمول:

1. **گیت شهری** — دسته‌های `needs_city` فقط برای شهرهای پشتیبانی‌شده باز است.
2. **قانون دنباله‌دار** — تا کتاب/سریال فعلی تمام نشده، از آن دسته آیتم جدید
   پیشنهاد نمی‌شود؛ به‌جایش بلوک «در حال انجام» یادآوری می‌کند.
3. **ضد تکرار** — آیتمی که در ۳۰ روز گذشته پیشنهاد شده دوباره نمی‌آید. اگر
   استخر خالی شد، قوانین مرحله‌به‌مرحله شل می‌شوند تا صفحه هرگز خالی نماند.

### دستور مدیر، عملی

در پنل ادمین یک «مناسبت» بساز با منبع «دستور مدیر»، تاریخ امروز، اولویت بالا
(مثلاً ۵۰) و آیتم‌های دلخواه در «آیتم‌های قفل‌شده». اگر فقط برای یک روز خاص است،
فیلد «سال» را هم پر کن تا سال بعد تکرار نشود.

پیشنهادها در جدول `DailyRecommendation` ذخیره می‌شوند، پس رفرش صفحه چیزی را
عوض نمی‌کند. فیلد `score` برای دیباگ در پنل ادمین قابل مشاهده است.

## ML

مدل و نحوه‌ی استفاده در [`docs/ml.md`](docs/ml.md) توضیح داده شده: Naive Bayes چندجمله‌ای
به‌ازای هر کاربر (`journey/ml.py`)، فقط برای بازچینش بخش «متناسب با حالت»، با
آستانه‌ی فالبک ۱۰ رکورد بازخورد.

### مود «غمگین» یعنی چه؟

تصمیم محصولی: نه محتوای هم‌حال، نه شادیِ تصنعی. برای مودهای منفی، تگ‌های
«امیدوارکننده» و «دلگرم‌کننده» وزن مثبت می‌گیرند و «تلخ» با وزن منفی سرکوب
می‌شود. این قاعده در `seed_base.py` (جدول `MOODS`) نوشته شده و بدون تغییر کد،
از پنل ادمین قابل تنظیم است.

## مدل مود

لیست ثابت ۹تایی برای کاربر، ولی هر مود مختصات عددی `energy` و `valence` بین
۲- تا ۲+ دارد. UI ساده می‌ماند و در عوض تقویم و آمار می‌توانند عدد واقعی نشان
بدهند. اضافه‌کردن مود جدید یک ردیف است، نه بازنویسی نگاشت.

## تقویم شمسی

`journey/jalali.py` تبدیل میلادی↔شمسی، طول ماه، سال کبیسه، نام ماه و روز
هفته را بدون هیچ پکیج بیرونی انجام می‌دهد. تاریخ‌ها میلادی ذخیره می‌شوند و
فقط موقع نمایش شمسی می‌شوند.

## داده

- `content/fixtures/top_titles.json` — ۲۰۰ فیلم و ۵۰ سریال برتر. تگ‌ها به‌طور
  خودکار از ژانرها ساخته می‌شوند (`content/taxonomy.py`). برای عوض‌کردن فهرست
  فقط همین فایل را عوض کن: `python manage.py import_titles --file mylist.json --clear`
- کتاب، کافه، ورزش، مدیتیشن، نوشتن، بازی و پادکست در `seed_base.py` به‌صورت
  نمونه آمده‌اند؛ بقیه از پنل ادمین دستی وارد می‌شوند.
- **مهم‌ترین ریسک پروژه همین‌جاست:** موتور بدون آیتم تگ‌خورده چیزی برای گفتن
  ندارد. هر آیتم تازه‌ای که وارد می‌کنی، حتماً دو سه تگ هم برایش بزن.

## تست

```bash
python manage.py test
```

۲۶ تست: تبدیل تاریخ شمسی (رفت و برگشت سه سال)، ثبات پیشنهاد در طول روز،
افزایشی بودن لایه دوم، قانون دنباله‌دار، گیت شهری، ضد تکرار، اثر بازخورد روی
پروفایل، ترتیب دسته‌بندی‌ها، مناسبت از هر دو تقویم، برنده‌شدن دستور مدیر،
شرطی‌بودن پیشنهاد کافه، جدا بودن دو پنل، فلوی ورود با OTP، رندر همه صفحات، و دو تست مدل ML (آستانه‌ی فالبک و یادگیری از بازخورد).

## کارهای باقی‌مانده

- فایل فونت وزیرمتن به‌صورت لوکال (فعلاً از Google Fonts می‌آید، پس بدون
  اینترنت فالبک سیستمی رندر می‌شود و فاصله‌ها کمی فرق می‌کند).
- سرویس پیامک واقعی برای OTP و هش‌کردن کد در دیتابیس.
- طراحی دقیق فیگما برای صفحات دسته‌بندی و پروفایل (بقیه پیاده شده‌اند).
- انتقال به PostgreSQL — فقط بلوک `DATABASES` در `config/settings.py`.
